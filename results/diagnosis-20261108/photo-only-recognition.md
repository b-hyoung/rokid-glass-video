# 외부 사진 등록 후 미인식 분석 — 2026-11-08

대상 영상: `녹음 2026-11-08 195527.mp4` (5.4초). 운영 서버에서 견훤·마주봄 각 1장, 640×360 사진의 저장 및 연결 영상 키를 확인했다. 두 대상 모두 appearance 벡터는 없다. 운영 matcher.js, vision-worker.js, library.js의 SHA-256이 로컬 최신 코드와 동일했다.

## 확정 재현

실제 운영과 같은 OpenCV.js / Matcher로 등록 원본 자체를 매칭했다.

| 등록 사진 | 참조 특징점 | 일치점 / RANSAC 일치점 | 가로 / 세로 분포 | 최종 탐지 |
|---|---:|---:|---:|---:|
| 견훤 | 500 | 500 / 500 | 64.36% / 38.31% | 1 |
| 마주봄 | 500 | 500 / 500 | 34.18% / 25.88% | 0 |

`cloud/matcher.js`의 supportsBounds는 참조 사진 전체에 대한 특징점의 가로·세로 분포를 각각 32% 이상 요구한다. 어두운 여백이 많고 작은 글자가 중앙에 집중된 마주봄 사진은 동일 원본조차 이 조건을 만족하지 못한다. 이는 등록 누락이나 사용자 촬영 문제에 의존하지 않는 판정 규칙의 문제다.

## 녹화 영상에서 추가로 막히는 단계

녹화에서 균등 추출한 12장으로 카메라 영역을 잘라 540×960으로 복원했다. 화면 녹화를 다시 압축·복원한 표본이므로 안경 원본 프레임과 수치가 완전히 같다고 볼 수 없다.

현재 OpenCV.js로 전체 화면과 네 방향 64% 타일을 모두 검사했다(현행 엔진은 전체 화면과 순환 타일 1개를 검사). 전체 화면에서 마주봄 일치 후보 수는 8, 1, 4, 4, 4, 1, 2, 1, 3, 2, 3, 1개였다. 필요 후보 수는 12개다. 전체 60회 검색 중 후보 부족 53회, RANSAC 일치점/비율 부족 6회, 영역 분포 탈락 1회였다. 두 신규 대상의 최종 탐지는 0회였다.

화면 속 제목이 작은 데다 카메라 촬영·모니터 표시·원근·흐림으로 원본 글자 특징이 바뀐다. 기본 ORB의 500개 특징점 예산이 선반·책·키보드·배선 등에도 쓰인다. 사진만 등록한 대상은 AppearanceMatcher.setReferences 필터에서 제외되므로 기존 벡터 기반 영역 검색이 보완하지 않는다. 외부 사진 업로드는 현재 자동 벡터 생성까지 수행하지 않는다.

## 수정 방향 (이 분석에서는 운영 추가 변경 없음)

1. 사진 전체의 고정 32% 기준 대신 등록 사진의 실제 특징점 분포를 기준으로 대응 영역을 검증한다. 충분한 RANSAC 일치점과 공간적 일관성 검사는 유지한다.
2. 등록 참조의 여러 축척, 영역별 특징점 분배, 국소 검색으로 작은 제목의 매칭을 보완한다. 일치점 기준을 일괄 하향하는 것만으로 해결하지 않는다.
3. 사진만 올려도 특징 벡터를 자동 추출해 기존 후보 검색에 활용하는 방안을 검증한다. 비슷한 제목·다른 사진·배경에 대한 오인식 대조가 필요하다.
4. 등록 원본 자기 매칭, 여백이 많은 실제 제목 사진, 화면을 다시 촬영한 영상과 다른 제목을 회귀 검증에 포함한다. 이전 합성 이미지 성공은 이 사례의 검증을 대신하지 못했다.

Python OpenCV의 별도 탐색 실험에서는 특징점 예산과 참조 축척을 함께 바꾸면 기하 매칭 통과가 개선됐지만, 현행 영역 판정과 오인식 대조까지 통과한 운영 수정으로 간주하지 않는다.


## 후속 수정 및 운영 배포 완료

- 실제 특징점 영역을 사진마다 계산해 빈 여백의 고정 32% 요구를 제거했다. 고유 대응점 12개, RANSAC 일치점 10개, 일치 비율 45%, 참조·현재 장면 양쪽의 공간 분포 검사는 유지한다.
- 외부 사진 전용 원본·65%·45% 참조와 1,800개 특징점 검색을 추가했다. 추가 축척은 대상당 최대 4개 뷰로 제한하고, 고밀도 검색은 한 스캔당 전체 또는 부분 영역 한 번만 수행한다. 기존 대상의 네 방향 타일 순서는 보존한다.
- 작은 중앙 제목의 불안정한 원근 외삽은 오차 조건을 통과한 아핀 변환으로 안정화한다. 대안 변환은 RANSAC 일치점 10개 이상, RMS 오차 3px 이하, 최대 오차 6px 이하에서만 사용한다.
- 실제 등록 사진·7개 대상 전체를 사용한 OpenCV.js Worker 재현: 문제 녹화 표본 12장 탐지 0/12 → 12/12, 추적 ID 1개, held 판정 0회. 마지막 실행의 분석 시간은 약 337~610ms였다.
- 녹화 결과와 추가 통신 지연 100ms를 인메모리 서버에 전달한 시험에서 진행률 100%와 마주봄 영상 재생 명령 1회를 확인했다. 실제 안경으로 재생 명령을 보내는 시험은 아니다.
