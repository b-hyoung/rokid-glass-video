# 안경 영상 진단 로그 수집

Windows에서 저장소의 `안경-진단-로그-시작.bat`을 더블 클릭한다. 창을 열어 둔 채 Chrome 제어 웹을 화면에 표시하고 안경 촬영을 시작해 끊김을 재현한다. 녹화도 함께 하면 발생 시점을 대조하기 쉽다. 시험이 끝나면 수집 창에서 Ctrl+C를 눌러 중지한다. 로그 위치가 창에 표시되며 기본 저장 위치는 `recordings/diagnostics/`이다. 이 폴더는 Git에 올라가지 않는다.

터미널에서 시간과 서버 주소를 지정할 수도 있다.

```powershell
python -X utf8 tools/collect_glass_diagnostics.py --duration 120
python -X utf8 tools/collect_glass_diagnostics.py --url http://localhost:8787 --interval 1
```

Python 표준 라이브러리만 필요하다. 기본적으로 1초 간격으로 `/cam/stats`를 읽고 UTF-8 JSONL에 한 줄씩 저장한다. 성공 시 원본 응답 전체, 요청·응답의 UTC 시각, 요청 소요 시간 및 서버 HTTP Date를 남긴다. 실패도 오류 행으로 기록하고 계속 시도한다. 요청이 오래 걸리면 실제 간격이 1초보다 길어질 수 있고 시험 종료 시 기록된 end 행에 횟수가 표시된다.

## 해석 시 주의

- 운영 서버에 읽기 요청만 보낸다. 촬영 명령, 데이터 삭제 또는 영상 저장은 하지 않는다. 로그에는 안경 상태와 서버 메시지 등이 들어갈 수 있으므로 공유 전에 확인한다.
- 서버 상태와 서버 상세 수신 기록을 저장한다. 초당 프레임 수는 집계값이며, 상세 기록의 단위는 개별 프레임이 아닌 영상 조각이다. PC 수집기는 브라우저가 화면을 지운 이유를 기록하지 않으므로 웹 진단 로그를 함께 내려받는다. 이 로그만으로 최초 병목 구간을 확정할 수 없다.
- 뷰어 목록에는 여러 브라우저가 있을 수 있고 안정적인 식별자가 없다. 순서가 바뀔 수 있으므로 배열 순번을 같은 뷰어로 가정하면 안 된다. `visible`, `at`, `seq`를 확인한다. 시각 `at`은 서버가 마지막 지표를 받은 시각이며, 이전 값이 계속 남을 수 있다. 가능하면 다른 제어 웹을 닫는다.
- `tele`의 `sent`, `drop`은 영상 프레임이 아닌 전송 조각의 누적값이다. `test`가 바뀌거나 카운터가 초기화되면 전후 차이를 계산하지 않는다. 값의 증가 시각은 보고 주기보다 정밀하지 않다.
- 로컬 기록 시간, 서버 시각, 안경 내부 시계는 다를 수 있다. 이들을 단순히 빼서 단방향 지연으로 해석하지 않는다.

## 상세 전송 기록

서버 상세 기록이 배포된 이후에는 이 수집기가 `/cam/diagnostics`도 읽어 같은 JSONL에 `server_trace`로 저장한다. 안경이 이미 전송한 영상 조각 순번·안경 전송 시각, 서버 수신 시각·크기, 카메라 영상 연결 시작·종료·오류·서버 복구 이벤트를 포함한다. 영상 바이트, 등록 이미지와 카메라 식별자는 포함하지 않는다. 종료 코드는 상대편 사유를 항상 설명하지 않는다.

서버는 최신 4096개 이벤트를 메모리에만 보관한다. 서버가 재시작되거나 메모리 상태가 사라지면 기록이 끊길 수 있고, 수집이 느려 범위를 넘기면 `lost`가 표시된다. `epoch`와 `reset`을 확인하고 시험이 끝날 때까지 수집기를 계속 실행한다. 네트워크 요청은 순차적으로 실행되므로 실제 주기가 길어질 수 있다. `server_trace_error`가 반복되면 상세 서버 기록을 받지 못한 것이다.

웹의 진단 로그 버전 3에도 도착한 각 조각의 안경 전송 시각과 서버 수신 시각을 넣는다. 같은 시험의 연속된 순번에 대해서만 안경 전송 간격과 서버 수신 간격을 계산한다. 안경과 서버의 시계 기준이 다르므로 절대 시각끼리 빼서 단방향 지연을 구하면 안 된다. 웹에서 받지 못한 조각도 확인하려면 PC 수집기의 서버 상세 기록이 필요하다. 이 기록만으로 안경 내부 카메라와 인코더 중 어느 쪽이 멈췄는지 구분할 수 없다.
