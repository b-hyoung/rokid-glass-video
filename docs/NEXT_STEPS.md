# Rokid 작업 인계 · 0.2.10

작성일: 2026-11-07. 이 문서는 다음 세션에서 이어 할 작업과 검증 한계를 기록한다.

## 현재 결과

- 운영 웹: https://glass-2412.youqlrqod.workers.dev/recognition
- APK: https://glass-2412.youqlrqod.workers.dev/downloads/glass-video-0.2.10.apk
- 로컬 APK: `build/glass-video-0.2.10.apk` (versionCode 12). 빌드 산출물은 Git에서 제외한다.
- 배포 버전: `4311be15-7cde-4489-8b4c-32ec054e53bb`.
- 내부 추적: Chrome OpenCV가 대상 정체와 특징 조각을 보내고, 안경의 작은 YUV 영상에서 Java 패치 추적으로 현재 위치를 확인한다. 최대 15Hz·4대상이며, 가림·불확실성·정체 확인 만료 시 표시를 없앤다. 전체 객체 인식이 안경으로 이전된 것은 아니다.
- 영상 로딩·재생 중 다른 대상의 자동 재생을 차단한다. 안경 버튼/탭으로 종료하며, 지연 명령과 오래된 재생 콜백을 차단한다.
- PC의 ‘안경 표시 확인’은 안경이 실제 그린 대상 ID·이름·위치와 영상 표시 상태를 재현한다. 광학 화면 캡처는 하지 않는다.
- 영상과 HUD 상태는 별도 WebSocket을 사용한다. HUD는 최대 4Hz, 미확인 메시지 1개로 제한한다. 공용 HTTPS 443과 무선망·기기 자원은 공유하므로 성능 영향이 완전히 없다고 보장하지 않는다.
- 등록된 대상 1개(`테스트`)와 이미지 8장을 보존했다. 삭제하지 않았다.

## 다음 작업 순서

### 1. ‘지우고 새로’의 범위를 먼저 확인

사용자는 ‘지우고 새로하자 다른것들도’라고 했지만 삭제 대상이 확정되기 전에 커밋·푸시와 문서화를 요청했다. **아직 삭제 승인이 구체화되지 않았다.**

- 대상·등록 이미지만 초기화할지, 연결 영상·앱 설정도 포함할지 확인한다.
- 확정된 범위를 백업한 뒤 초기화한다. 현재 등록 데이터는 Cloudflare Durable Object에 있으며 Git 소스를 지워도 초기화되지 않는다.
- 서버 전체 삭제, 저장소 초기화 또는 기존 영상 삭제로 확대 해석하지 않는다.

### 2. 새 물건으로 등록·인식 시험

예정 대상은 Rokid 선글라스 상자, VR 기기, 마주봄 판넬/인쇄면이다. 실제 시험 물건은 사용자가 준비한 것으로 확정한다.

1. APK 0.2.10을 기존 앱 위에 설치하고 Chrome 운영 웹을 새로고침한다.
2. 촬영 시작 후 기존 HUD/카메라 가이드를 실제 거리에서 보정한다. 현재 보정은 거리와 눈-카메라 시차를 완전히 해결하는 3D 보정이 아니다.
3. 대상마다 이름과 연결 영상을 선택한다. 영상 등록으로 정면·좌우·거리 변화의 장면을 수집하고 검토해 저장한다. 같은 대상에 여러 이미지를 추가할 수 있다.
4. 하나씩 인식한 뒤 두 물건이 동시에 들어오는 장면을 시험한다. 무늬가 적은 VR 외형이나 뒷면은 인식이 어려울 수 있다.
5. 중앙 조준으로 해당 영상만 시작되는지 확인한다. 재생 중 다른 물건을 봐도 바뀌면 안 된다.
6. 로딩 중/재생 중 각각 버튼과 탭으로 종료한다. 늦은 재생 명령이 영상을 다시 켜지 않는지 확인한다. 종료 뒤 중앙을 비우고 다시 조준한다. 같은 대상 재생은 시야 밖 2초 후 재진입도 확인한다.

### 3. 실물 안경의 내부 추적과 성능 검증

APK 빌드·자동 검증은 통과했지만 실제 안경 카메라/버튼/발열 시험은 미완료다. 빌드 당시 ADB 연결 기기가 없었다.

- `/cam/stats` 로그의 ‘내부 추적 사용’ 여부, `tele.tracking`, `trackMs`, `tracks`를 확인한다.
- YUV 동시 출력이 지원되지 않으면 내부 추적을 끄고 기존 영상 촬영·서버 위치 표시로 돌아간다. 실패 사유를 기록하고 장치의 출력 크기·최소 프레임 시간·세션 지원을 점검한다.
- 30/40/60fps 각각 실제 수신·해석·표시 fps, 끊김, 발열, 배터리 변화를 기록한다. 40fps는 하드웨어 요청값이다.
- 두 물체의 독립 이동, 머리 회전, 가림, 시야 이탈·재진입, 조명 변화에서 이름이 다른 물체로 옮겨 붙지 않는지 본다.
- 카메라 영상과 HUD 좌표는 -90도 회전 및 화면 비율을 맞춘다. 틀어지면 센서/YUV/인코더 크기와 중앙 크롭부터 확인한다.
- 표시 대기열을 늘려 끊김을 숨기지 않는다. 기존 영상 표시 200ms 대기 상한과 최신 프레임 복구 동작을 유지한다.
- 0.5초 미만의 촬영→표시 지연은 실물 기준으로 별도 측정한다. 서버 도착 시각이나 JVM 처리 시간을 실측 지연으로 해석하지 않는다.

### 4. 안경 표시 정보와 PC 웹 대조

- 안경이 실제 표시한 이름·개수·위치가 PC ‘안경 표시 확인’에 나타나는지 확인한다.
- 로딩→재생→버튼 종료 상태가 실제 앱과 일치하는지 본다.
- 연결 단절 시 PC에서 약 2.2초 후 오래된 표시가 사라지고, 재연결 시 최신 상태만 표시되는지 본다.
- 카메라 프레임 연결과 HUD 연결이 별개인지 확인한다. 캡처 영상을 추가로 전송하지 않는다.
- HUD 활성화 전후 촬영/표시 성능을 같은 조건에서 비교한다. 공유 네트워크·CPU 영향까지 ‘0’이라고 단정하지 않는다.

## 유지할 방향과 보류 사항

- 인쇄면·상자는 특징 기반 매칭과 짧은 추적을 우선 사용한다. 무늬가 적거나 입체적인 대상은 여러 각도의 참조를 늘려 먼저 평가한다.
- 정확한 3D 테두리보다 올바른 대상 이름과 자연스러운 선택, 오래된 표시 제거가 우선이다.
- SAM/HOLa를 통한 등록 영상의 객체 영역 추출, 별도 인스턴스 인식 모델, OnePose 계열 3D 방식은 후보이며 이번 버전에 구현한 기능이 아니다. 실패 사례를 모은 다음 필요성을 결정한다.
- Cloudflare 운영을 유지한다. 다른 호스팅을 권한다면 사용자가 요청했던 실제 Claude와의 적대적 검증을 먼저 진행하고 결과를 남긴다. 이번 작업에서는 호스팅 변경을 권하지 않았다.
